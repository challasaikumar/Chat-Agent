# Database

## Engine

- **Supabase Postgres** (any Postgres 15+ works, including local) via **postgres.js** (`postgres`)
- **Drizzle ORM** (`drizzle-orm/postgres-js`) schema in `apps/api/src/db/schema.ts`
- Migrations in `apps/api/drizzle/` (SQL generated by drizzle-kit). The previous SQLite migrations are archived in `apps/api/drizzle-sqlite-archive/` and are **not** applied.
- **Full-text search** uses Postgres `tsvector` + GIN indexes (`apps/api/src/db/fts.ts`):
  - `messages.search_vector` – generated stored column
  - `memory_facts.search_vector` – trigger-maintained (includes the linked entity name)
- Supabase is the **database host only**. App auth stays cookie-session based (`users`, `auth_sessions`); Supabase Auth is not used. `apps/api/src/db/supabase.ts` is an optional supabase-js helper (not used by the ORM).

## Connection

Set `DATABASE_URL` (Supabase Dashboard → Project Settings → Database → Connection string → URI).

| Mode | Port | When |
| --- | --- | --- |
| Direct / Session pooler | 5432 | **Recommended for the long-running Fastify API** |
| Transaction pooler | 6543 | Works too (prepared statements are disabled automatically); use for serverless/short-lived clients |

SSL is enabled automatically for non-local hosts. `DATABASE_POOL_MAX` (default 10) controls the pool size. `DATABASE_PATH` is removed (ignored with a warning).

Local development without Supabase: `postgresql://postgres:postgres@127.0.0.1:5432/minimi`.

## Major tables

| Table | Purpose |
| --- | --- |
| `users` | Accounts, Argon2id hash, role/status |
| `auth_sessions` | Hashed session + CSRF tokens |
| `audit_events` | Security audit (no message bodies) |
| `conversations` / `messages` | Chat source of truth |
| `memory_facts` (+ `search_vector`) | Durable memory with provenance |
| `entities` / relationships / summaries | Project graph |
| `research_snapshots` / `research_sources` | Web research |
| `research_claims` / temporal tables | Historical claims & comparisons |
| `agent_runs` / tool call tables | Orchestration audit |
| Evidence assessment tables | Source/claim verification |

All user-owned rows cascade from `users` where FKs are defined. Authorization still filters by `user_id` in repositories. Timestamps are `timestamptz`; JSON columns are `jsonb`.

> If you use Supabase's Data API (PostgREST), enable RLS on these tables or keep them out of the exposed schema — the API connects with the database role and does not rely on RLS.

## Migrations

```bash
npm run db:generate   # after schema edits (drizzle-kit)
npm run db:migrate    # apply to DATABASE_URL (fails with a clear message if unset)
```

`npm run start` / `npm run dev` also apply migrations on API boot. The bootstrap runs under a Postgres advisory lock and also applies the FTS setup (idempotent).

## Tests

Database-backed Vitest suites need a **disposable** Postgres in `DATABASE_URL_TEST` (must differ from `DATABASE_URL`). Each test database creates its own schema and drops it on cleanup. Without `DATABASE_URL_TEST` those suites are skipped.

```bash
DATABASE_URL_TEST=postgresql://postgres:postgres@127.0.0.1:5432/minimi_test npm test
```

## Backup / restore

Supabase provides managed backups (and PITR on paid plans). For ad-hoc dumps use `deploy/scripts/backup-db.sh` (`pg_dump`, custom format) and `deploy/scripts/restore-db.sh` (`pg_restore`, stop writers first). Use a direct/Session URL (port 5432) for dump/restore.

## Limitations

The API holds its own connection pool; keep `DATABASE_POOL_MAX` within your Supabase plan's connection limit (or point `DATABASE_URL` at the pooler).
